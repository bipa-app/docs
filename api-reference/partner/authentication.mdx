## API Key Authentication

All Partner API requests require authentication using an API key passed in the `X-API-Key` header.

```bash
X-API-Key: your_partner_api_key
```

## Making authenticated requests

Include your API key in the `X-API-Key` header of every request:

```bash
curl https://api.bipa.app/v1/events \
  -H "X-API-Key: your_partner_api_key" \
  -H "Content-Type: application/json"
```

## Verify your key

`GET /v1/me` returns the partner the key belongs to. It takes no parameters: the key is the identity, so a key can only ever read its own partner.

```bash
curl https://api.bipa.app/v1/me \
  -H "X-API-Key: your_partner_api_key"
```

```json
{
  "partner_id": 89,
  "name": "Acme",
  "kind": "originator"
}
```

`kind` is `controller` or `originator`. Projeto Ponte partners reach the same endpoint at `https://api.agentispay.co/me` (sandbox: `https://api-sandbox.agentispay.co/me`).

## Obtaining API keys

Create sandbox and production keys from **API keys** in the [Bipa Business portal](https://infra.bipa.app/keys). Production access requires an approved organization. You can keep up to four active keys per partner and environment, so you can separate integrations and rotate a key before revoking its predecessor.

<Note>
  A key identifies one partner in one environment. The partner ID comes from the key; do not send a partner ID to select an account. Keep the key secure and never share it publicly.
</Note>

Choose **read only** or **read and transact** when creating a key. Existing keys retain read and transact access. Read-only keys can call GET and HEAD routes; POST, PATCH, PUT, and DELETE requests return `403`. Access cannot be changed on an issued key. [See key permissions](/api-reference/partner/key-access).

## Security best practices

### Use environment variables

Store API keys in environment variables, not in code:

```bash
export BIPA_PARTNER_API_KEY=your_partner_api_key
```

```javascript
const apiKey = process.env.BIPA_PARTNER_API_KEY;
```

### Never expose keys in client-side code

Partner API keys should only be used in server-to-server communications. Never include them in frontend applications or mobile apps.

### Rotate keys if compromised

If you suspect your API key has been compromised, revoke it in the Bipa Business portal and create a replacement. Contact Bipa if you cannot access the portal.
